# 내 아이디어에 맞게 바꾸기

박스의 배치와 역할은 출발점입니다. 남길 기능을 고르고, 필요 없는 것을 지운 뒤 기능 하나를 구현해보세요.

## 먼저 내 서비스를 한 문장으로

> [누구]가 [어떤 일]을 하는 웹사이트

예: 신입생이 학교 주변의 공부할 장소를 찾는 웹사이트.

## Codex에 요청할 때

**어디를 → 어떻게 바꿀지 → 어떤 결과를 기대하는지**를 말해주세요. 아래 예시 중 필요한 것 하나를 사용하고, 새로고침해서 결과를 확인합니다.

| 하고 싶은 일 | 요청 예시 |
| --- | --- |
| 위치 옮기기 | `starter의 로그인 박스를 소개 문구 왼쪽으로 옮겨줘. 모바일에서는 세로로 배치해줘.` |
| 필요 없는 기능 빼기 | `내 서비스에는 날씨가 필요 없어. starter의 날씨 박스와 그 박스의 안내를 없애고, 지도 영역을 넓혀줘.` |
| 역할 바꾸기 | `나만의 기능 영역을 공부 장소 검색 영역으로 바꿔줘. 장소 이름을 입력할 검색창부터 만들어줘.` |
| 새 박스 추가하기 | `지도 아래에 ‘내가 저장한 장소’ 영역을 추가해줘. 먼저 빈 상태 안내만 보여줘.` |
| 서비스 설명 바꾸기 | `이 서비스는 신입생이 공부할 장소를 찾는 사이트야. 이름과 소개 문구를 그 목적에 맞게 바꿔줘.` |

처음에는 작은 변화 하나부터 요청하세요. 기능을 한꺼번에 여러 개 만들면 어느 부분에서 문제가 생겼는지 찾기 어려워집니다.

## 기능을 요청하는 틀

```text
내 서비스는 [누구]가 [어떤 일]을 하는 웹사이트야.
starter의 [박스 이름]에 [필요한 기능]을 구현해줘.
사용자가 [행동]하면 [결과]가 보이게 해줘.
필요한 계정이나 API 설정이 있으면 먼저 알려줘.
구현한 뒤 내가 직접 동작을 확인하는 방법도 알려줘.
```

기초 틀의 예시처럼 Google 로그인·지도·기상청을 사용해도 되고, 자기 아이디어에 맞는 서비스를 찾아 적용해도 됩니다. 필요하지 않은 API를 억지로 넣지 않아도 됩니다.

## 변경 후 확인

- 바꾸려던 문구·박스만 원하는 대로 바뀌었나요?
- 화면을 좁혀도 내용이 잘 보이나요?
- 지우지 않은 다른 박스의 안내와 요청문 복사가 되나요?
- 실제 기능을 구현했다면 정상·실패 상황을 모두 확인했나요?
