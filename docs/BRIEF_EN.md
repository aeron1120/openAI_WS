## Purpose and Learning Outcomes

- Student need: After building a first app, students need a repeatable way to improve one feature, check that it works, and keep a recoverable record of the change.

- Why this topic: Following WS1's external connections, this session introduces local development, focused requests to Codex, and Git/GitHub through one small change.

- Outcomes: Run an app locally; add and test a favorites button; commit and push the change to a personal repository; use revert in a separate practice repository and verify both the restored behavior and new commit.

- Partner organizations: TBD. Add only organizations whose participation and naming permission are confirmed.

## Activity and OpenAI Tools

- Activity: Compare the starter and completed meetup planner. Add independent favorites buttons with Codex, test select/deselect behavior, and record the change. Apply the same workflow to a personal project if ready.

- Campus Hub template: Self-made; starter and complete examples in [aeron1120/openAI_WS](https://github.com/aeron1120/openAI_WS) (currently private; access must be arranged before distribution).

- OpenAI tools used: Codex for reading the project, implementing one scoped change, and troubleshooting; ChatGPT for clarifying the request. Supporting tools: VS Code, Node.js, Git and GitHub.

- Demonstration: request → changed files/diff → browser checks → commit → push → GitHub verification. The separate revert exercise restores intentionally disabled buttons. Favorites reset on refresh; persistent storage is reserved for WS3.

## Preparation

- Participants: Laptop and charger; working Codex/ChatGPT and GitHub access; VS Code, Git and Node.js 20+ installed; a personal fork/clone opened and running before the session. Bring one feature idea.

- Venue and equipment: Projector and screen, power strips for laptops, stable Wi-Fi, seating that lets organizers walk between rows.

- Organizers: Check account access and repository permissions; rehearse the starter, complete and recovery examples; prepare offline copies. Offer setup support 15 minutes before the session and pair participants if setup fails.
